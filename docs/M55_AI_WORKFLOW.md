# M5.5：AI 进入调仓流程

入口：AI 页菜单 → 预设流程、提案与记分卡；组合与调仓页 → AI 提案与记分卡、风险限额；设置 → 风险限额。设计见 [产品设计 §6.7](PRODUCT_DESIGN.md) 和 [AI 助手 §13.5–13.9](AI_ASSISTANT.md)。

## 提案

AI 给出具体的买入、加仓、持有、减仓、卖出或观望建议时调用 `propose`，存进 `ai_proposal`。提案卡不是操作卡：存提案不改账户，所以不用确认。

- 单只建议（`single`）一次只写一只：方向、建议仓位、价格区间（可选）、期限（交易日）、基准、理由、失效条件。批准不等于下单；要下单仍然让 AI 生成下单卡，或自己去下单页。
- 调仓方案（`rebalance`）是整个账户的目标组合：每只给目标权重，合计不超过 100%，未列出的持仓按 0，余下是现金。你点「批准并预检」后，App 按最新策略调用 M5 的调仓服务预检，生成一份调仓计划，同一张卡变成**批量操作卡**：逐笔列出委托、引擎预校验（含风险校验）、资金冻结和补单规则。点「执行」一次按已确认的限价和数量提交；报价变化不重算委托，仍用最新行情校验交易规则、资金和风险，盘中报价须不超过 60 秒。资金不够同时买时按钮变成「先卖后买」；持仓、费率改变或想按最新价重算时点「重新预检」。之后的补单、撤单、执行报告和手动调仓完全一样。
- 状态：待你决定 → 已批准 / 已拒绝 → 已执行。重置账户后旧提案不能在新账户执行，但到期仍然对账。
- 读过外部内容（资讯、联网搜索、MCP）的那一轮生成的提案卡，和操作卡一样标「本轮读过外部内容」。

## 决策日志

`decision_journal`：理由、预期、失效条件、期限、基准。

- 下单页买入时，委托确认里可以写（不写不记）。期限默认 20 个交易日，基准沪深300ETF。
- 调仓计划确认时可以写「这次调仓的理由」，每只买入各记一条，期限 5 个交易日，基准用策略的基准；先卖后买的买单在确认那一刻就记。AI 提案生成的调仓，来源记为「AI 提案」，理由是提案的理由。

## 记分卡

到期（到期日 15:30 以后）按基准对账：起点是提出当天（非交易日顺延到下一个交易日）的前复权收盘价，终点是到期日的收盘价（停牌用之前最近的一根）。

- 区间收益：单只就是这只的涨跌；调仓方案按目标权重加权，现金收益按 0。
- 超额 = 方向 ×（标的收益 − 基准收益）。买入 / 加仓 / 持有方向 +1，减仓 / 卖出 −1，观望不计命中率，只记录。
- 命中 = 超额大于 0。AI 的提案和你自己的决策分开统计；AI 提案生成的调仓日志算在提案里，不重复计。被拒绝的提案也照样对账：记分卡看的是建议准不准，不是你采纳了多少。
- 已对账少于 20 条标「样本太少」。缺日线时记下原因，下次打开再试。
- 打开「提案与记分卡」页或 AI 调 `get_scorecard` 时对账。记分卡和提案状态不进记忆。

## 风险限额

存在账户状态 `risk` 里（重置账户时沿用，和费率一样算「你的券商」设置），默认全部关闭。在引擎校验里执行：下单页、AI 操作卡、调仓预检和执行都用同一套，被拦下的规则名是「风险限额」。

- 单票上限：买入后这只证券（持仓市值 + 未成交买单 + 这笔）占总资产的比例。
- 单日换手上限：当天委托金额（已成交按成交额、未完成按委托价，买 + 卖，废单不算）加这笔，占总资产的比例。
- 禁买 ST。
- 只拦买入：卖出是降低风险的操作，不拦，但卖出金额计入当日换手。总资产 = 资金余额 + 持仓市值，没有行情的持仓按买入均价成本估。
- AI 可以用 `set_settings` 的 `risk_*` 参数生成改限额的操作卡；下单卡多一行「风险校验」。

## 新的只读工具

工具从 27 个变成 36 个，仍是固定列表、按名字排序（升级后缓存重建一次）：

| 工具 | 说明 |
| --- | --- |
| `propose` | 记下建议或调仓方案（见上） |
| `get_portfolio` | 风险限额、策略（带版本）、最近的调仓计划和执行报告 |
| `get_journal` | 决策日志 |
| `get_scorecard` | 记分卡和最近 10 条提案（会先对一遍到期的账） |
| `query_local_db` | 本地库只读 SQL：只能一条 SELECT / WITH，不能 RECURSIVE；只能查快照、日线、证券、分红送配、交易日历、事件日志、执行报告、某日证券状态；在 `PRAGMA query_only` 下执行，最多 200 行，5 秒超时 |
| `screen` | 横截面选股：候选池是排行（成交额前 100 + 涨 / 跌幅前 100）或自选、持仓，不是全市场，结果里写明 |
| `get_analysis` | 账户分析指标（和账户分析页同一套） |
| `get_corp_actions` | 某只证券的分红送配（东方财富）或本地的除权除息日历 |
| `get_benchmark` | 基准的区间收益和最近收盘 |

`get_fee_profile` 同时给 code、price、qty 时，再按当前费率算这笔的逐项费用和保本价（和费用计算器同一套），AI 算费用不再心算。`navigate` 可以打开组合与调仓、调仓计划、提案与记分卡、预设流程、数据中心。

## 简报和预设流程

- 简报：交易日 15:30 前打开 AI 页提示盘前简报（开盘后提示「要不要补一份」），15:30 后盘后简报，周五收盘后到周日周报。点了才发：App 把持仓、未完成委托、除权除息、调仓和执行报告、交割单、记分卡拼成 `<briefing_data>`，和输出模板一起放在最后一条用户消息里，在新对话里发一次请求。点「不用」当天不再提示。
- 预设流程：内置个股体检、周度复盘、调仓前检查，也可以自建（名称、步骤、输出模板、是否要填证券）。运行时在新对话里发「运行预设流程「…」」，步骤和模板作为附带内容放在最后一条用户消息里，不改系统提示。每个流程记最近 20 次运行，点开对比。

## 数字溯源和评测

- 回答结束后，App 把正文里的价格、金额、比例、日期和这一轮的工具结果、提问附带的上下文做匹配：四舍五入后相等、「万 / 亿」换算、「约」允许 3% 误差都算有来源；两个数字的差、和、积、商、涨跌幅算「算出来的」，但其中一个必须是回答里已经有来源的数字（否则 K 线上千个数字两两组合几乎什么都凑得出）。找不到来源的用虚线标出，回答下方显示「数字溯源：x 个有来源 · y 个算出 · z 个找不到来源」，点开看每个数字来自哪个工具。不检查列表序号、链接、指数名（沪深300、中证1000）、≤ 31 的不带单位整数和计数。
- 评测：`__tests__/ai/eval` 里 10 道固定题（5 类页面问「这是什么」、规则、费用、资讯、调仓提案、没授权的买卖咨询），工具结果来自录好的行情和资讯样本。每题检查：该调的工具调了、数字都能溯源、没有生成操作卡、提案数对。默认用录好的模型响应，不联网，随 `npm run check` 跑。换提示词或模型时联网跑：

```bash
AI_EVAL_BASE_URL=https://… AI_EVAL_KEY=sk-… AI_EVAL_MODEL=… AI_EVAL_PRICE=3,0.3,3.75,15 npm run eval:live
```

`AI_EVAL_PROTOCOL` 默认 anthropic，`AI_EVAL_AUTH` 默认 bearer；结束时打印输入 / 输出 token 和估算费用。
