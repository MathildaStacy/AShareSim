# 交易引擎（M1）

> 2026-10-26 · 代码在 `src/engine/`，测试在 `__tests__/engine/`。规则依据是 [TRADING_RULES.md](TRADING_RULES.md)。

引擎是纯 TypeScript，不依赖 React Native，也不读系统时钟：时间和行情都由外部喂进来。所以实时模拟、单元测试和以后的回放模式（M6）用的是同一套代码。

## 1. 模块

| 文件 | 内容 |
| --- | --- |
| `units.ts` | 整数金额：价格用厘（0.001 元），金额用分，费率用亿分之一。四舍五入到分 |
| `calendar.ts` | 交易日历。2026 年休市日由真实日 K 线反推，测试逐日核对 |
| `securities.ts` | 板块识别、各板块规则表（最小价位、申报单位、单笔上限、价格笼子）、涨跌停价自算（只做交叉校验） |
| `session.ts` | 交易时段：哪个时段委托怎么走（券商暂存 / 集合竞价 / 连续竞价 / 下一交易日）、能不能撤单、能不能下市价单 |
| `fees.ts` | 佣金、印花税、过户费、经手费、证管费；合并计佣；买入冻结；红利税税率；交割单校准（反推佣金率、判断免五） |
| `validate.ts` | 下单校验（§3），结果分两种：券商拦下（不生成委托）和交易所拒收（废单） |
| `matching.ts` | 撮合：逐档吃单、挂单排队、成交价穿过委托价、集合竞价。纯函数，输出「成交计划 + 成交依据」 |
| `account.ts` | 账户：可卖数量（T+1）、可用、可取、持仓（摊薄成本和买入均价两种口径） |
| `engine.ts` | 引擎：下单、撤单、喂快照、推进时间、日终清算、跨日（扣红利税、除权除息、派息） |
| `types.ts` | 快照、委托、成交、批次、交割单、账户状态、引擎事件 |

## 2. 怎么用

```ts
const engine = new Engine(newAccount('2026-10-26'), { calendar: new TradingCalendar(), security: lookup });
engine.deposit({ date: '2026-10-26', t: T(9, 0) }, 30_000_000);          // 30 万元
engine.placeOrder({ date: '2026-10-26', t: T(9, 0) }, { code: 'sh510300', side: 'B', kind: 'limit', price: 4130, qty: 1000 });
engine.onSnapshot(snapshot);   // 接入层校验水位、去重后喂入，返回成交、撤单等事件
engine.advance(now);           // 没有行情时也要推进时间：报送暂存委托、15:30 清算、跨日
```

- 账户状态 `engine.state` 是纯数据，M2 直接存进 SQLite。快照缓存是临时的，不需要存。
- 每个调用都返回事件列表（下单、废单、撤单、成交、清算、红利税、派息、红股），界面层用它弹提示、写 AI 的操作日志。

## 3. 撮合要点

全部按「不确定就保守」处理：

| 情况 | 做法 |
| --- | --- |
| 连续竞价主动成交 | 按快照盘口逐档吃单，成交价是各档价格；同一个快照里我们自己的多笔委托不重复吃同一档 |
| 挂单排队 | 前面的量 = 挂单时本方该价位的挂单量；之后成交价等于委托价时，用成交量增量先消耗前面的量 |
| 成交价穿过委托价 | 全部成交，价格是委托价（价格优先，这个价位的单子必然都成交了） |
| 对手盘挂到委托价以内 | 按委托价和对手盘的量成交 |
| 开盘集合竞价 | 价格优于开盘价：按开盘价成交。等于开盘价：竞价后本方在这个价位还有剩余挂单，就不成交、排在剩余后面；开盘即涨停（买）/ 跌停（卖）同样不成交 |
| 收盘集合竞价 | 连续竞价没成交的挂单 14:57 起参加；规则同开盘。竞价成交量拿不到时按 0 处理，不成交 |
| 盘后固定价格 | 只按 15:05 以后观察到的成交量增量成交，价格是收盘价 |
| 市价单 | 只看五档；即时成交剩余撤销、全额成交或撤销都按五档的量判断。沪市 4 种、带保护限价（不超过它成交，转限价的价格也不超过它），深市 5 种 |
| 预埋单 | 报送时（9:15）再查一次涨跌停，超出就是废单；9:30 / 13:00 报送的还要查价格笼子 |

每笔成交都记录依据（规则、快照时间、档位、该档的量、排队量、成交量增量、竞价价格和成交量），并生成一句说明，例如「10:00:03 快照卖2 11.13 挂 400，主动成交 400，按该档价格成交」。

`npm test -- __tests__/engine`，共 83 项（M2 第 1 步加了 3 项，第 3 步加了 7 项，第 4 步加了 8 项（见第 8 节）；第 3 步的是：沪市市价类型和保护限价、ST 不能市价、预检 `check`；`__tests__/market`、`__tests__/sim` 是适配层和运行时的测试）：

| `src/sim/refresher.ts` | 刷新循环和后台跟踪的开关逻辑 |
| `android/.../tracker/` | 前台服务 `TrackerService`（specialUse + Headless JS 任务 + 唤醒锁）和 `BackgroundTracker` 原生模块 |

引擎为此改了三处，都只会让成交更少：

1. 两次快照间隔超过 `MAX_QUEUE_GAP_SEC`（20 秒）不消耗排队量。
2. 开盘集合竞价没观察到 9:25–9:30 的快照（App 9:25 以后才打开）时，委托价等于开盘价的不成交、排在当时的挂单后面；以前会用当日累计量和当时的盘口判断，偏乐观。
3. 补出来的快照（`Snapshot.reconstructed`）没有盘口：委托不在它上面「到达」，集合竞价按没观察到处理，排队位置记为未知（`UNKNOWN_QUEUE`），只按穿价成交。

另外 `Engine.primeSnapshot()` 让 App 重启后用本地存的最后一个快照做比较基准。

后台跟踪的取舍（2026-10-26 和你确认，手机是小米 15 Pro / HyperOS）：

- 交易日 9:00–15:30、有今天能成交的委托时开前台服务（第二天才报送的预埋单不算），只刷新这几只，默认 5 秒一次；委托都结束、收盘或在通知上点「停止跟踪」（当天不再自动开）就停。设置里可以改成交易时段全程（完整录快照）或关闭。
- 前台服务只能在 App 在前台时启动，所以条件满足时 App 在前台就先开着，通知上显示今日流量。
- 被杀、断网时的兜底就是上面的补撮合。
- 模拟器（Android 16）核对：回到桌面、锁屏并强制进入深度 Doze 后，快照照常每几秒一个。HyperOS 杀后台更激进，需要在系统设置里把本 App 的省电策略设为「无限制」。

## 7. M2 第 3 步：交易界面用到的引擎接口

- `Engine.check(now, req)` / `Simulator.checkOrder(req)`：下单前预检，和 `placeOrder` 走同一个 `validateFor`，不推进时间、不改状态；返回校验结果和这笔委托会怎么走（暂存 / 集合竞价 / 连续竞价 / 下一交易日 / 盘后）。下单页每次重画都调用它，被拦下时写明违反哪条规则。
- `OrderRequest.protect`：沪市市价单的保护限价（必填）。最优五档剩撤 / 转限价只吃到保护限价以内的档位，转限价、对手方最优、本方最优的价格不超过它；买入冻结用 `freezePriceOf`（限价 = 委托价，沪市市价 = 保护限价，深市市价和不带价的盘后单 = 涨停价）。
- 表单上的换算（解析价格、可买数量、仓位快捷键、预估费用、价格笼子提示、报送时间、能不能撤单）在 `src/sim/orderForm.ts`，成交详情的费用算式在 `src/sim/fillExplain.ts`，交割单 CSV 在 `src/sim/ledgerCsv.ts`，当日参考盈亏在 `src/sim/pnl.ts`，都是纯函数并有测试。

## 9. M6：输入记录和回放

`Engine.recorder`（`EngineRecorder`）记下引擎的每次输入（`EngineInput`）：下单、撤单、转账、改费率 / 上限 / 限额、分红送配变化、改了状态的时间推进、会改变状态的快照（这只证券有未完成委托，或者推进时间时改了状态）。`begin(date)` 在每个带日期的输入改状态之前调用，记录器据此在每个交易日第一次输入前记一个起点。引擎为此加了 `snapshots()`、`corporateActions()`、`memo()` / `restoreMemo()`（按日记下的集合竞价成交量基准），撮合逻辑没有改。

- 实时账户：`src/replay/journal.ts` 的 `JournalWriter` 挂在 Simulator 的引擎上，和账户状态、`account_event` 同一个事务写进 `engine_input`。
- 重放：`src/replay/runner.ts` 的 `applyInput` 把一条输入喂给引擎；下单前先恢复下单那一刻这只证券的快照和集合竞价成交量基准。
- 核对：`src/replay/verify.ts`；回放练习：`src/replay/practice.ts`。口径见 [M6_REPLAY.md](M6_REPLAY.md)。
