# M4.1 合并前功能与界面审计

日期：2026-10-28。比较基点：`d58db4b`（main），首次实现：`f077fb5`。审计范围为本次 M4.1 功能与新增/修改的 Android 页面，不扩展为整套产品重设计。

审计依据：`PRODUCT.md`、`DESIGN.md`、`docs/AI_ASSISTANT.md` §13.1–13.4 和产品设计 M4.1。仓库没有单独的 issue-tracker / coding-standards 配置；本次直接以已有设计文档为规格。代码分别做 Standards / Spec 独立审计，并在修复后复核。

## Standards

首次发现 3 项，现已全部关闭：

- **P1：URL 认证信息可能进入明文设置、日志及 AI 页面上下文。** `key`、百分号编码的参数名未被旧规则覆盖；整条 URL 解码也可能把密钥中的 `%26` / `%2F` 当成分隔符。显示与保存现在共用认证识别，原始或解码形式任一含认证信息就拒绝保存、整体隐藏；测试覆盖别名、双重编码、userinfo 和编码分隔符。
- **P2：第二个 Tushare 服务跳过认证探测。** 唯一前缀 `tushare2` 不再用于识别服务，改为规范化官方端点；重复预设、自定义前缀和非 Tushare 地址均有回归。
- **P2：camelCase 写工具可绕过写操作名称优先规则。** 拆分 camelCase / 缩写边界后检查写动词，`deleteAccount`、`getAndDelete` 等不能靠 `readOnlyHint` 放行。

唯一有实际影响的代码结构问题是验证/展示重复维护密钥规则；已统一。复核执行了真实导出函数，原泄漏复现路径均已关闭，没有剩余已知阻断项。

## Spec

首次发现 3 项，现已全部关闭：

- **P2：Tushare 认证探测依赖工具前缀。** 与 Standards 同一项，按端点修复。
- **P2：资讯字段变化被静默解释为有效数据。** 字符串年份曾被替换为设备年份、字符串页数被当作 PDF-only、缺失公告日期被过滤为空结果。现校验必要标题、标识、日期、年份和页数，安全转换数字字符串，其余返回 `FeedFormatError`，不会猜测年份或误称没有公告。
- **P2：Kimi 搜索错误未作为外部资料隔离。** 远端错误也包在 `external` 标签内；“搜索失败 → 生成操作卡”的链路测试确认显示外部来源提示。

额外发现并修复：切换聊天模型原先丢失 MCP 选择。现保留会话选择，并按当前模型实际能力显示开关生效状态。复核未发现修复引入的实际回归。

Standards 共 3 项（最高 P1），Spec 共 3 项（均 P2，1 项与 Standards 重复）；全部已关闭。
