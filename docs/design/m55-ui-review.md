# M5.5 UI 收尾审查

日期：2026-10-28。范围：预设流程、提案与记分卡、聊天中的提案/批量操作卡、风险限额设置。沿用现有浅色交易界面和暖白聊天界面。

## 已处理的问题

| 问题                                                 | 调整                                                                                                                 |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 流程首页以工具名、缓存机制解释功能，难以快速判断用途 | 每个流程先显示用途；步骤、思考强度和输出模板按需展开。运行按钮直接写出流程名称，按内容宽度靠右排列，减少重复的大色块 |
| 运行历史写着“对比”，实际只是打开聊天                 | 改为“运行记录”，折叠保存，记录行用箭头提示可打开对应聊天                                                             |
| 没有到期样本时，记分卡重复显示占位数字和警告         | 显示“暂无到期结果”和未到期/观望数量；计算方法与样本不足解释放入“记分卡怎么算”，对账错误仍直接显示                    |
| 提案列表将创建日期、状态、期限、对账日挤在一行       | 拆开状态与期限；可打开的提案增加箭头，辅助文字使用较深的次要文字色                                                   |
| 长 ETF 名称与目标比例在窄屏大字号下相互挤压          | 按窗口宽度和系统字号切换为上下排列；期限/对账日与基准单独排布。标准字号仍保留两列                                    |
| 0 笔委托仍提示“一次确认提交”并可执行                 | 明确显示“本次无需提交委托”，执行入口显示“无需执行”且不可点；保留重新预检                                             |
| 风险限额说明包含实现细节，保存控件偏小               | 改为限制范围及当前设置，保存按钮至少 48dp，说明提高文字对比度                                                        |
| 流程编辑与大字号控件空间不足                         | 增加键盘避让，输入框、主要按钮和记录行至少 48dp；按钮组和页签可换行                                                  |

## 验证

- `npm run check`：45 个套件、545 项测试通过；TypeScript 通过；ESLint 无错误，保留 2 条原有测试文件 warning。
- 保留提案批准/预检/执行、风险拦截、流程请求与自定义流程校验测试；补充 0 笔委托不可执行的回归，并验证折叠后的方法说明和流程步骤仍可打开。
- Android 17 ARM64 模拟器：1280×2856 / density 480 / 1.0 倍字体，以及 1125×2436（375dp）/ 1.3 倍字体。实际查看了流程列表、步骤、历史、编辑表单及键盘、记分卡和决策日志、长名称提案、批准后的批量卡与风险设置。
- 运行记录可打开原聊天；编辑表单可在键盘打开时滚动到保存/取消。系统深色模式下仍按项目既定浅色主题显示，可读性正常。
- 用本地 MockRelay 生成 `UI-review rebalance` 提案 #3，批准后为 0 笔委托的计划 #11，用于核验空操作状态。前后 SQLite 快照确认委托记录完全相同，风险限额仍全部关闭；快照 `after-ui.db` 已保存。
- 验收后恢复标准屏幕尺寸、1.0 倍字体和系统浅色模式。
