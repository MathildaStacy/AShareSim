AI 助手 v0.4 重新设计

左边是可以直接点的手机原型。回答是本地模板，不联网；「获取模型列表」返回的是模拟数据，模型名只作演示。

改了什么

  1. 输入框下面一排：模型 · 搜索 · 思考。三个设置跟着对话走，随时能改，不用进设置页。新对话沿用你上一次的选择。
  2. 「AI 服务」拆成「供应商」和「模型」。供应商 = 协议 + Base URL + API Key。填好后点「获取模型列表」，App 请求 GET /models 列出这个 Key 能用的模型，你勾选哪些出现在选择器里。一个 Key 配一次，就能用它下面所有模型。
  3. 能力标签。每个模型标出思考档位、联网搜索、上下文长度。认识的模型按名字自动识别；中转服务里不认识的标「能力未知」，可以手动标注。不支持工具调用的模型标黄：它读不了行情和持仓，只能聊天。
  4. 不支持的选项是灰的。模型不支持搜索时「搜索」按钮变虚线，点了说明原因并列出能搜索的模型；思考强度只能选这个模型有的档位。
  5. 改设置的代价写清楚。对话里已经发过消息时，换模型、改思考强度、开关搜索都会让缓存从头重建。输入框上方出现黄条，写明要重建多少 tokens，可以一键改回；发出去以后对话里插一条分隔线。
  6. 回答的结构：思考过程（折叠）→ 搜索了什么、看了哪些网页（折叠）→ 读了哪些 App 数据 → 正文带 1 引用 → 来源列表 → 用量。

联网搜索怎么发

供应商方式
Anthropic服务端工具 web_search，结果和引用随回答返回
OpenAIResponses 的 web_search 工具
通义千问请求参数 enable_search: true
Kimi内置函数 $web_search（App 原样回传一次参数）
智谱 GLMtools 里加 web_search
OpenRouter模型名后加 :online
DeepSeek不支持
自定义按协议：Anthropic / Responses 用 web_search 工具；Chat Completions 中转发 web_search_options，要你手动标注支持

搜索按次额外计费（各家价格不同），用量里单独写次数。

思考强度怎么发

协议字段
Anthropic Messagesthinking: adaptive + output_config.effort；关闭 = 不发 thinking
OpenAI Responsesreasoning.effort；关闭 = none
Chat Completions 兼容reasoning_effort 或厂商参数（enable_thinking、thinking.type）。只有开关的模型显示「关闭 / 开启」两档；总是思考的模型（deepseek-reasoner、kimi-k2-thinking）不能关

和现有设计冲突的地方

  • AI_ASSISTANT.md §6.1 写「工具列表固定」「模型和思考强度按服务固定」。现在改成同一段缓存里固定：开搜索会在工具列表里多一个 web_search，工具在请求最前面，所以整段前缀重算。也因此搜索是按对话开关，不是按问题自动开。
  • 国产模型和多数中转只有 OpenAI Chat Completions 接口，要新增第三种协议（现在只有 Messages 和 Responses）。

确认后要改的代码

  • types.ts：AiService 拆成 Provider（协议、地址、鉴权、缓存参数、Key 末 4 位、模型列表）和 ModelEntry（id、启用、能力覆盖、价格）；Effort 加 max / on；Thread 记下模型、思考、搜索。
  • protocol.ts：新增 Chat Completions；按供应商拼搜索和思考参数；新增 listModels()（Anthropic 带 x-api-key + anthropic-version，其他用 Bearer）。
  • 数据迁移：旧的每个服务变成一个供应商 + 一个已启用的模型。
  • 同步改 AI_ASSISTANT.md §6、PRODUCT_DESIGN §6.5 和 prototype.html 的 AI 页。
