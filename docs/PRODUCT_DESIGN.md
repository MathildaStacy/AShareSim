# AShareSim 产品设计

> 版本 0.2 · 2026-10-26 · 产品经理：Claude · 负责人：boren.fang
> 配套：[交易规则规格](TRADING_RULES.md) · [AI 助手：上下文与记忆](AI_ASSISTANT.md) · [可交互原型](design/prototype.html) · [量化学习路线](research/quant-roadmap.html)

## 1. 为什么做

学量化之前，先要真正懂你要交易的市场：一笔单子什么时候能成交、按什么价成交、要交哪些钱、为什么今天买的明天才能卖。券商模拟盘规则太宽松，看书又没有手感。
AShareSim 用**真实行情 + 真实规则 + 真实税费**做模拟交易，再把量化路线图前几个阶段需要的数据、指标和练习放进同一个 App。

只有入金是模拟的。

## 2. 目标和不做的事

| 目标 | 怎么衡量 |
| --- | --- |
| G1 练习炒股，了解 A 股规则和税费 | 路线图阶段 0 的两条通关标准能在 App 里完成并自动打勾 |
| G2 为个人量化打基础 | 阶段 1–3 的练习数据能从 App 导出，App 给出「标准答案」对照；阶段 7 的周度执行记录能在 App 里完成 |
| 模拟和真实一致 | 用真实交割单校准后，费用逐项误差为 0；成交模型「只会更保守」 |

不做：真实下单、连接券商、荐股、跟单、社区、资讯推送、杠杆。AI 只做分析和讲解，**不能替你下单**。

## 3. 用户

只有一个用户：你自己。Java / Go 后端背景，刚开始学 Python 和量化，资金规模 ≤ 40 万。所以：

- 不需要账号体系和后端，所有数据留在手机上（本地优先，和 NovelCreationPartner V1 一致）。
- 讲解要从「为什么」讲起，但不啰嗦；术语第一次出现时可以点开看解释。
- 界面习惯参考同花顺、东方财富：红涨绿跌、五档盘口、底部 Tab、持仓 / 委托 / 成交 / 交割单的叫法完全沿用。

## 4. 覆盖路线图的哪些阶段

| 阶段 | App 里对应什么 | 说明 |
| --- | --- | --- |
| 0 了解 A 股交易规则 | 模拟交易本身 + 规则课 + 费用计算器 + 集合竞价演示 | 核心。练习「用集合竞价买一手宽基 ETF，查看交割单」在 App 里完成后自动打勾 |
| 1 Python 数据分析 | 数据导出（日线 / 指数 / 我的成交）+ 练习题 + 标准答案 | Python 在电脑上写，App 负责给数据和对答案 |
| 2 统计和投资基础 | 账户分析：收益、波动、夏普、回撤、beta / alpha、跟踪误差、信息比率 | 每个指标都能点开看公式和代入数字后的计算过程 |
| 3 搭建本地数据库 | 数据中心：本地行情库、增量更新、数据质量检查、腾讯 / 新浪交叉核对、「某天的股票状态」查询 | App 的本地库就是一个小号的阶段 3 作业 |
| 7 模拟执行（提前做） | 调仓计划 → 集合竞价预埋单 → 成交记录 → 周度打卡（连续 12 周） | 路线图说券商模拟盘太松，正好用本 App 的保守撮合 |

阶段 4（单因子）、5（回测）、6（机器学习）在电脑上做，不进 App。阶段 8 的「书面交易纪律」做成一个轻量功能放在阶段 7 里。

## 6. 功能清单（V1）

### 6.1 行情

- 数据：腾讯行情 `qt.gtimg.cn`（快照、五档、涨跌停价、市值、PE/PB）、`web.ifzq.gtimg.cn`（分时、日 / 周 / 月 K，前复权 / 不复权）。前台 3 秒刷新，后台停止。
- 自选：增删、拖动排序、按涨跌幅 / 现价排序。
- 行情 Tab：8 个主要指数（上证、深成、创业板、沪深 300、中证 500 / 800 / 1000、科创 50），各板块涨幅 / 跌幅 / 成交额排行。
- 个股详情：分时（均价线、成交量）、K 线（MA5/10/20、成交量）、五档盘口、成交明细、F10 简况、**本股规则卡**（属于哪个板块、涨跌幅、申报单位、价格笼子范围、当前能不能撤单、你的可卖数量和原因）。

### 6.2 交易（核心）

- 下单页沿用同花顺布局：左边代码 / 价格 / 数量 / 可买可卖 / 仓位快捷键（全仓、1/2、1/3、1/4），右边五档。下方实时显示**预估费用明细**。
- 价格类型：限价 + 按交易所区分的市价类型（见规则 §6.2）。
- 校验失败时直接告诉你违反了哪条规则，并能一键跳到对应规则课。
- 委托确认弹窗（同花顺有，保留）。
- 委托状态：未报 / 已报 / 部成 / 已成 / 已撤 / 部撤 / 废单，和券商一致。
- 成交详情：成交依据（规则 §6.3）。
- 交割单：逐项显示佣金、印花税、过户费、（可选）经手费、证管费、股息红利税补，可导出 CSV。
- 盘后固定价格交易。
- 清算：每个交易日 15:30 后执行日终清算（T+1 解锁、可取资金更新、除权除息、交割单生成）。App 不在前台时，下次打开补算。

### 6.3 资金（唯一的「模拟」部分）

- 银证转账：「银行转证券」就是模拟入金。默认累计净入金上限 40 万（可改）。
- 资金流水：入金、出金、买卖、费用、红利、红利税补。
- 重置账户：旧账户归档（可查看、可导出），不删除。

### 6.4 学习

- 路线图卡片：阶段 0/1/2/3/7，练习和通关标准可勾选；能由 App 数据判断的项（例如「完成一次集合竞价买入宽基 ETF 并查看交割单」）自动打勾。
- 规则课：T+1、涨跌停、交易时间与集合竞价、价格笼子、申报单位与零股、交易费用、红利税、除权除息、ST 与退市、新股前 5 日、各板块差异。每课 1 屏讲解 + 1–3 道小测 + 「去实践」。
- 费用计算器、集合竞价演示（拖动买卖单，看开盘价怎么按「成交量最大」原则产生）。
- 数据练习：路线图阶段 1 的练习，提供 CSV 下载和「标准答案」（App 用同一份数据算出的每年收益、年化波动、最大回撤等）。
- 账户分析：阶段 2 的全部指标，可选基准沪深 300 / 中证 800；每个指标显示公式和代入过程；样本少于 20 个交易日时标注「样本太少，不具备统计意义」。
- 数据中心：阶段 3 的缩小版——本地库表一览、最后更新时间、增量更新、数据质量检查、交叉核对、某日股票状态查询（是否在主板池、是否停牌、是否开盘涨跌停）。
- 模拟执行：本周调仓清单（手动录入或导入 CSV）→ 生成周一集合竞价预埋单 → 成交后自动记录 → 未成交按固定规则补单 → 周度打卡、连续周数、执行偏差。书面交易纪律（加仓条件、暂停条件、不加杠杆）。

### 6.5 AI 助手

- 用途：介绍公司、介绍股票、分析走势和财务、解释规则和某笔费用、复盘我的交易。**不荐股、不下单**，每个回答带「仅供学习，不构成投资建议」。
- 协议：OpenAI Responses API、Anthropic Messages API（和 NovelCreationPartner 一样）。用户配置多个服务（名称、协议、Base URL、API Key、模型），可测试连接。Key 存 Android Keystore / iOS Keychain。
- 数据：AI 通过只读工具获取数据，而不是靠模型记忆：`get_quote`、`get_kline`、`get_company_profile`、`get_financials`、`get_positions`、`get_orders`、`get_trades`、`get_fee_profile`、`get_rule`。界面上显示 AI 调用了哪些工具（例如「读取 贵州茅台 近 120 日 K 线」），回答里的数字都能追溯。
- **页面上下文**：每个页面声明「用户正在看什么」（页面名 + 页面上看得到的关键数据 + 表单内容和校验结果），每次提问自动附带。用户可以直接问「这是什么意思」「解释这个页面」。从 AI 返回别的页面再打开 AI，对话里插一条「你现在在：xxx」分隔线。
- **最近操作**：本机记录操作日志（浏览、委托、被拦截、废单、撤单、成交、转账、设置、学习、导出），每次附带最近 10 条（可选 0 / 5 / 10 / 20）。所以「刚才那笔为什么是废单」不用解释是哪笔；更早的记录通过 `get_activity` 工具查。
- **对话记忆**：
  - 多个对话，各自保存在本机。对话超过 20 条消息时，较早部分由模型压缩成摘要，只发送摘要 + 最近 8 条原文。
  - 跨对话不自动带原文，需要时用 `search_conversations` 检索其他对话的摘要（「我们上次聊了什么？」）。
  - 长期记忆：你说过的背景、偏好、计划、约定（例如「不做短线」「五粮液是练习仓」），由模型调用 `remember` 写入，可设为自动记住 / 先问我 / 关闭，全部可查看、修改、删除。持仓、成交、费率、行情这些 App 里有最新值的数据**不进记忆**，每次现查，避免过时。
- 快捷问题随页面和最近操作变化：刚有废单时第一个是「刚才那笔为什么是废单？」，在个股页有「介绍这家公司」，还有「解释这个页面」「我们上次聊了什么？」「复盘我今天的交易」等。
- 透明：AI 页顶部的上下文条（页面 · 操作数 · 记忆数）可以点开，看到这次会发送的全部内容、每部分的 token 数和实际请求结构；每条提问下注明「附带：……」。
- 省钱：请求按「不变的在前、变的在后」排列，并打好缓存断点（Anthropic 用 `cache_control`，OpenAI 用 `prompt_cache_key`）；历史只追加不改写，记忆按对话拍快照，模型和思考强度按服务固定。每条回答下方显示缓存读 / 写 token 和估算费用。
- 每次发送前显示预计 token 用量和预计走缓存的部分。请求结构和缓存策略见 [AI_ASSISTANT.md](AI_ASSISTANT.md) §6。

## 7. 视觉

- 浅色为主（同花顺风格），支持深色。红涨绿跌（可在设置里反转）。
- 数字用等宽数字（tabular-nums），价格精度按品种（股票 2 位、ETF 3 位）。
- 密度高于一般 App：交易类页面一屏要看到五档和下单表单。

## 8. 技术方案（概要）

| 层 | 选择 |
| --- | --- |
| App | React Native 0.87 + TypeScript，Android 先行（iOS 结构保留，后补） |
| 状态 | zustand |
| 存储 | op-sqlite：`quotes_snapshot`、`kline_day`、`adj_factor`、`corp_action`、`security`（含板块 / ST / 上市日）、`trade_calendar`、`account`、`cash_ledger`、`order`、`fill`、`position_lot`（按批次，红利税先进先出要用）、`settlement`、`fee_profile`、`lesson_progress`、`activity_log`、`ai_thread`、`ai_message`、`ai_memory` |
| 引擎 | 纯 TypeScript、无 UI 依赖：`rules/`（板块、涨跌停、价格笼子、时段）、`fees/`、`matching/`（规则 §6）、`settlement/`；全部用 Jest 单元测试，用真实交割单做测试用例 |
| 行情 | 腾讯接口为主；分红送配用东方财富数据中心；新浪做交叉核对 |
| AI | 直连用户配置的服务，Responses / Messages 两种协议，无状态请求（App 自己管理历史和摘要），工具调用循环有轮数上限；上下文组装见 [AI_ASSISTANT.md](AI_ASSISTANT.md) |
| CI | 沿用 NovelCreationPartner 的 GitHub Actions：lint + tsc + jest、Android debug APK |

## 10. 决定记录与待决问题

已决定（2026-10-26）：

| 问题 | 决定 |
| --- | --- |
| 佣金费率 | 按真实数据：用你的真实交割单校准，App 反推佣金率和是否免五并更新设置。校准前用占位值（万 2.5、最低 5 元），并在下单页、交割单、费用计算器、AI 回答里标注「未校准」 |
| 分红送配数据 | 用东方财富数据中心接口补充 |

还待你决定：

1. 持仓成本口径：默认「摊薄成本」（同花顺 / 东财默认），要不要同时显示「买入均价」？

3. 浏览记录要不要算进「最近操作」？现在算（AI 能知道你从哪个页面过来），可以在设置里把条数调成 0 关掉。
