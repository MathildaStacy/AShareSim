# M5：组合与调仓 + 数据中心

入口：交易 / 我的 → 组合与调仓；学习 → 组合与调仓、数据中心。

## 每周流程

1. 建立策略：名称、股票池、频率、基准、单票上限、补单规则与书面纪律。修改生成新版本，历史计划保留原版本。
2. 录入整个账户的目标组合。支持手动权重 / 股数、UTF-8 CSV / JSON 文件选择和粘贴。未列出的持仓按目标 0 处理；低于 100% 的权重保留现金。
3. 预检：复用交易引擎，显示逐只买卖数量、可卖股数、T+1 / 停牌 / 价格笼子 / 涨跌幅 / 资金阻塞、最低佣金增加额、整手后的权重误差。科创板买入 200 股起、1 股递增。盘中超过 60 秒的报价不能生成/提交计划。
4. 批量确认：列出每笔限价与数量，以及授权的补单规则。提交时重新校验，价格、持仓或费率改变后需重新预检。资金不足可以回去降低权重，也可以先卖后买；卖单未成交前不增加可用资金。
5. 跟踪执行：委托详情可直接打开。补报仅针对未成交买单，9:30 后在连续竞价、报价不超过 60 秒时，先撤原委托，再按卖一价补报剩余数量一次。先卖后买等待卖单结束后尝试；资金或整手校验不通过则记录放弃，不暗中缩单。14:50 撤销剩余委托；错过当日窗口不跨日追单。自动操作依赖 App 前台或现有后台跟踪，受系统停进程影响。
6. 复盘：挂单全部结束后填写本周复盘，生成不可变报告，同时停止本次调仓的后续补单。目标没有差额也可记录主动不调仓的理由。漏执行另记原因，不计连续周数。按北京时间自然周（周一开始）去重，同一账户连续 12 周报告自动完成阶段 7 两个执行打卡项。

策略的股票池与频率是人工执行约定，不是选股器或定时建单器。上市满一年和新股特殊状态缺乏可靠历史元数据时，界面明确提示人工核对。单票上限、计划外委托及相反方向委托在报告中标记，不阻止已确认的交易。

## v1 目标交换格式

CSV（UTF-8，可带 BOM）：

```csv
version,1
code,weight
sh510300,30%
sz159915,20%
```

权重也可以写 `0.3`，不能写 `30` 表示 30%。股数使用表头 `code,shares`，数值必须为非负整数。中文表头 `代码,目标权重` / `代码,目标股数` 也接受。

JSON：

```json
{"version":1,"mode":"weight","targets":[{"code":"sh510300","value":0.3},{"code":"sz159915","value":0.2}]}
```

JSON 权重只接受 0–1 数字。股数模式为 `mode:"shares"`。重复代码、负数、非有限值、权重合计超过 1、未知版本或缺列均报错，不部分导入。六位代码自动加沪深前缀，指数及不支持证券由行情分类和引擎拒绝。

## 报告口径

每行关联原始委托、成交 ID 和交割单 ID；保存决策价格、所有下单价格、成交均价、成交比例、未完成原因、费用与整手误差。导出明细 CSV 与完整 JSON，价格以厘、金额以分记录。

- 价格滑点：买入为实际成交额减决策价金额；卖出反向。正值表示更差。
- 实际费用：本次关联成交的引擎费用总和，与对应证券买卖交割记录一致。未来补扣红利税和其他资金流水不并入这项。
- 最低佣金增加额：实际佣金减同一委托费率计算值；按实际合并计佣设置计算，补单是独立委托。
- 未成交机会损失：剩余计划数量 × 报告日最新价相对决策价的变化，卖出反向。
- 整手机会损失：理想目标股数与取整目标股数的差 × 报告日价格变化。
- 实现损失：滑点 + 实际费用 + 未成交机会损失 + 整手机会损失。
- 相对回测基线多损失：实现损失 − 理想全量按决策价成交、按计划时费率且不设最低佣金的费用。

缺少报告日行情时，相关机会损失及汇总为 null，界面显示「未计算」，不写成 0。已生成报告保留当时结果，不用之后行情重写历史。

## 数据中心

- 本地表数量与最新记录：行情快照、日线、证券资料、每日证券状态、分红送配、日历、账户事件、双源核对。
- 不复权日线：首次最近 1,000 根；之后回看最后日期前 7 天，主键去重覆盖，当日数据可盘中更新。
- 质量检查：OHLC、非有限数值、负成交量、重复日期、非交易日、区间内缺失交易日。内置休市日历只完整覆盖 2026 年，其他年份单独提示待核对，不据此推断日线缺失。缺行不直接判定停牌。
- 腾讯 / 新浪双源核对：最新价、前收、开盘、成交量；日期不同或相差超过 10 秒视为不可比，保存源时间和核对结果。
- 某日状态：基于 M5 启用后观察到的行情保存主板 / ST / 停牌 / 开盘涨跌停状态；历史无记录显示未知。当前证券资料不会反向覆盖历史。

## 持久化与执行边界

Schema 5 新增 `strategy_version`、`rebalance`、`execution_report`、`weekly_skip`、`account_event`、`security_day`、`data_check`。账户仍整行 JSON。事件与账户更新同事务写入，只追加。调仓使用独立引擎副本保留盘口消耗量；委托、账户、关联 ID 和补单次数同事务提交，失败不发布副本。交易与行情写操作串行化；重复确认和重启后的补单以数据库状态去重。重置账户后历史报告保留且不参与新账户执行。

M5.5 的 AI 调仓提案、风险限额和批量操作卡见 [M55_AI_WORKFLOW.md](M55_AI_WORKFLOW.md)。产品文档允许后置的影子组合不在本次实现中。
