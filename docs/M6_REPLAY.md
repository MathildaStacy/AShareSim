# M6：回放模式

> 2026-10-28 · 代码在 `src/replay/`，页面在 `src/ui/screens/Replay*.tsx`，测试在 `__tests__/replay/`、`__tests__/ui/replayScreens.test.tsx`。

入口：交易 Tab → 回放练习；学习 Tab → 回放练习。

## 1. 两件事

| 功能 | 做什么 | 用的数据 |
| --- | --- | --- |
| 回放练习 | 选一个录过快照的交易日，在沙盒账户里重新交易一遍；周末也能练 | `quotes_snapshot`（自选、持仓、有委托的证券，App 开着或后台跟踪时每个快照都存） |
| 核对实时模拟（验收） | 把某个交易日的实时模拟按记下的输入重放，和当天的委托、成交、撤单、清算逐笔比对 | `engine_input`（本版新增的输入日志）+ `quotes_snapshot` + `account_event` |

两者用同一个引擎（`src/engine/engine.ts`），没有为回放改撮合规则。

## 2. 回放练习

- **起点**：只有现金（5 / 10 / 20 / 40 万），或者「当天的真实账户」：输入日志里这天的第一个起点，也就是那天第一次操作前的资金、持仓（可以卖昨天以前买的）和已经挂着的委托。只能选有输入日志的日期。
- **证券**：这天有快照的证券，默认选录到三成以上的前 6 只，最多 10 只。名称和是否 ST 按那天数据中心记下的证券状态。
- **时钟**：从 9:10 开始，可以先挂预埋单，9:15 报送参加开盘集合竞价。暂停 / 1× / 10× / 60×；「跳到下一时段」依次是 9:15、9:25、9:30、11:30、13:00、14:57、15:00；午间休市直接跳到 13:00；到 15:00 自动暂停。时钟只往前走。
- **撮合**：时钟走到某一刻，就把这之前的快照按时间顺序喂给引擎，和实时模拟一样逐档吃单、排队、穿价成交、集合竞价。某只证券超过 5 分钟没有快照时页面提示「这段时间不会成交」。
- **不支持盘后固定价格交易**：快照里没有 15:05 以后的盘后成交量（实时模拟用的是当天分时，回放时已经拿不到）。
- **结束**：「快进到收盘并结束」把剩下的快照喂完、推进到 15:30 清算，算出盈亏、费用、委托和成交笔数，以及每只证券当天的收盘价。
- **存法**：`replay_session` 只存起点和你的操作（下单、撤单带当时的回放时间）以及时钟。重新打开时从头重算；引擎是确定性的，所以结果和离开时一样。被券商拦下的委托不存（它本来就不改变状态）。
- **沙盒**：不碰真实账户的状态、交割单、操作日志、调仓和记分卡；费率和风险限额沿用真实账户当前的设置（「你的券商」的设置）。

### 盲测

「盲测回放」从录到六成以上的交易日里随机选一天，默认选覆盖率最高的证券。结束前不显示日期和星期；可以选择连证券名称和代码一起隐藏（显示成「证券 A、证券 B」，保留板块，规则照常）。AI 的页面上下文也不带日期，并写明「不要推测或透露日期」。结束后揭晓。

## 3. 输入日志和核对

引擎不读系统时钟，同一个起点状态、同样顺序的输入，得到同样的事件。所以实时模拟只需要把输入记下来（`src/replay/journal.ts`）：

| kind | 什么时候记 | 内容 |
| --- | --- | --- |
| `seed` | 每个交易日第一次输入前；App 打开、重置账户时 | 账户状态（去掉前一交易日以前的已完成委托、成交、交割单，编号由 `seq` 接着发）、引擎里每只证券的最新快照、分红送配 |
| `place` | 下单（含被拦下的） | 时间、委托请求、引擎里这只证券当时的快照和集合竞价成交量基准、证券信息；设了风险限额时加上持仓证券的快照 |
| `cancel` / `deposit` / `withdraw` | 撤单、转账 | 时间和参数 |
| `fee` / `cap` / `risk` / `actions` | 改费率、入金上限、风险限额；分红送配有变化 | 新值 |
| `advance` | 推进时间时改了状态（跨日、报送暂存委托、清算） | 时间 |
| `snap` / `prime` | 喂快照：这只证券有未完成委托，或者它推进时间时改了状态；补撮合前的基准快照 | 已经存进 `quotes_snapshot` 的只记 code、t 和校验值；补出来的、没存的记全文 |

记录器挂在引擎上（`Engine.recorder`），输入日志和账户状态、`account_event` 在同一个事务里写库；批量调仓的事务失败时一起撤回。日志和快照一起清理：快照库里最早的日期之前的输入删掉（快照「永久保留」时不删）。

**核对**（`src/replay/verify.ts`，回放练习页 → 核对实时模拟）：

1. 读这天的输入，遇到 `seed` 就用它的状态新建引擎（App 重启以后引擎内存是空的，库里读出的状态才是真实起点），其余按顺序喂进去；快照引用到 `quotes_snapshot` 里取。
2. 如果这天还没清算（实时账户是在第二天第一次打开时清算的），推进到当天 23:59:59。
3. 回放出的事件和 `account_event` 里这一天的记录按不会再变的字段比对（委托：合同号、证券、方向、类型、价格、数量、时间；成交：成交编号、价格、数量、金额、费用、净额、时间、成交依据；撤单、废单的原因；清算；红利税、派息、红股），列出「实时有、回放没有」和「回放有、实时没有」。
4. 日终状态和下一个起点比对：资金、冻结、当日卖出回款、持仓、编号、每笔委托的状态和成交量。
5. 以下情况写进「没法核对」，结果不算一致：快照已经被清理；同一秒的快照被修正覆盖过（校验值对不上，按修正后的重放）；这天没有起点（M6 以前的日期）。

M6 的验收（产品设计 §9）：「回放一天的结果和当天实时模拟的结果逐笔一致」。测试 `__tests__/replay/verify.test.ts` 覆盖了预埋单开盘集合竞价成交、主动成交、排队后穿价成交、撤单、批量事务（失败一次、成功一次）、App 中途重启、第二天打开时清算；真实使用时在「核对实时模拟」里逐天看。

## 4. 决定（2026-10-28）

| 问题 | 决定 |
| --- | --- |
| 回放用哪个账户 | 沙盒账户，不影响真实账户；起点可以是现金或当天的真实账户 |
| 回放练习存什么 | 只存起点和操作，打开时重算。好处是不用存引擎内存（排队位置、已吃掉的盘口），结果不会因为存取而走样 |
| 盲测隐藏什么 | 默认隐藏日期，可选连名称和代码一起隐藏；板块和规则照常显示 |
| 盘后固定价格 | 回放里不提供：快照没有盘后成交量，按「不确定就不成交」处理就是永远不成交，不如不让下 |
| 核对怎么判定 | 委托、成交、撤单、废单、清算逐条一致，日终状态一致，且没有缺快照、被覆盖的快照，才算「逐笔一致」 |
